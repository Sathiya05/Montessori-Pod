# Little Roots Montessori

A complete, premium-quality, fully responsive Montessori-inspired learning pod website built with **HTML5, Tailwind CSS, and Vanilla JavaScript**.

**Brand:** Little Roots Montessori  
**Tagline:** "Growing Curious Minds, One Little Step at a Time."

## Project Overview
This project includes:
- Public marketing pages: Home 1, Home 2, About, Programs, Curriculum, Contact
- Frontend demo login portal with role-based redirects (Parent/Admin)
- Parent dashboard: child profile, daily learning logs (filters), teacher reports (modal view), attendance, tuition/payment demo, notifications with mark-as-read
- Admin dashboard: overview stats/charts, parents/students/teachers views, demo CRUD for students and teachers, learning log creation, teacher report creation, tuition management, enquiries management with search/filters/status updates
- Shared components injected via JavaScript: `js/navbar.js` and `js/footer.js` (no duplicated navbar/footer markup in HTML pages)
- Theme toggle (light/dark) and RTL toggle (LTR/RTL) with LocalStorage persistence and flash-prevention
- Locally downloaded royalty-free images in the `images/` folder

> **Demo limitations:** Authentication, dashboard data, contact enquiries, and payment actions are frontend-only demonstrations using `localStorage`. They are **not** secure for production. Real deployments must connect a backend, database, secure authentication/authorization, and a payment gateway.

## Technology Stack
- HTML5
- Tailwind CSS (configured build process via `tailwind.config.js`)
- Vanilla JavaScript (modular files in `js/`)
- Lucide icons (CDN script)
- Google Fonts (DM Serif Display, Nunito Sans)
- Local image assets
- LocalStorage for frontend demo persistence

No React, Next.js, Vue, Angular, or Bootstrap is used.

## Installation & Setup
### Prerequisites
- [Node.js](https://nodejs.org/) (LTS recommended) and npm

### Install dependencies
```bash
npm install
```

## Tailwind Setup and Build Commands
Tailwind is configured in `tailwind.config.js` with project colors, fonts, and content paths. Source styles are in `css/input.css` and the compiled output is `css/style.css`.

- **Development (watch mode):**
  ```bash
  npm run dev
  ```
- **Production/minified build:**
  ```bash
  npm run build
  ```

`css/style.css` is generated and listed in `.gitignore` (rebuild as needed).

## How to Run the Website Locally
1. Install dependencies and build CSS:
   ```bash
   npm install
   npm run build
   ```
2. Open `index.html` directly in your browser, **or** serve the folder with a simple static server (recommended for consistent behavior):
   ```bash
   npx serve .
   ```
   Then visit the provided local URL (e.g. http://localhost:3000).

## How to Update Brand Colors
Edit the `theme.extend.colors` section in `tailwind.config.js`:
- `primary` (Sage Green): `#78947A`
- `secondary` (Warm Terracotta): `#C77D5B`
- `accent` (Soft Butter Yellow): `#F3DFA2`
- `bg`, `surface`, `heading`, `body`, `border`
- `dark.bg`, `dark.card`, `dark.surface`, `dark.text`, `dark.muted`, `dark.accent`

After changes, rebuild Tailwind (`npm run build` or `npm run dev`).

## How to Replace or Add Images
- Place images in the appropriate subfolder under `images/` (e.g. `images/home/`, `images/programs/`, `images/teachers/`).
- Use descriptive filenames and provide meaningful `alt` text in HTML.
- Update `<img src="...">` paths in the relevant HTML/JS files.
- Prefer optimized images (WebP or compressed JPG). The project currently includes locally downloaded JPG assets from royalty-free sources (e.g. Unsplash).

## How to Edit Program Content
- **Programs page:** edit sections and the comparison table/cards in `programs.html`.
- **Home program cards:** `index.html` (and `home2.html` where applicable).
- **Program age ranges/schedules/tuition notes:** currently sample, configurable content in `programs.html` (easy to update in one place on that page).
- **Dashboard program lists:** demo data seeded in `js/admin-dashboard.js` (`seed()` function and related arrays).

## How to Manage Demo Dashboard Data
Demo data is stored in browser LocalStorage under keys such as:
- `lr-students`, `lr-teachers`, `lr-logs`, `lr-reports`, `lr-payments`, `lr-tuition-admin`, `lr-notifications`, `lr-enquiries`, `lr-session`, `lr-theme`, `lr-dir`

To reset demo data, clear the site's LocalStorage in your browser dev tools (Application/Storage tab) and reload the page; seed data will be recreated where applicable.

## Demo Login Credentials
> Frontend demo only. Do **not** use as secure production authentication.

- **Parent:** `parent@littleroots.demo` / `Parent@123` → redirects to `dashboard/parent-dashboard.html`
- **Admin:** `admin@littleroots.demo` / `Admin@123` → redirects to `dashboard/admin-dashboard.html`

`js/auth.js` contains comments indicating where real backend authentication and authorization must be connected.

## Theme and RTL Behavior
- **Theme toggle:** icon-only (sun/moon), available in desktop navbar and inside the mobile hamburger menu. Preference saved to `lr-theme` in LocalStorage and applied across all pages (including dashboards, forms, modals, cards, dropdowns, tables). An inline script in each page `<head>` prevents a flash of the wrong theme.
- **RTL toggle:** icon-only direction control, available in desktop navbar and inside the mobile hamburger menu. Toggles `dir` between `ltr` and `rtl` (and sets `lang`), saves to `lr-dir` in LocalStorage, and uses CSS logical properties for better RTL adaptation.

## Frontend Demo Limitations
- No real user accounts, password security, sessions, or authorization enforcement beyond client-side checks.
- Contact/enquiry form saves to LocalStorage; **no email is sent**.
- Tuition "Pay" actions and status changes are simulated; **no real payment is processed**.
- Admin/parent CRUD and records are LocalStorage-based and scoped to the browser/device.
- Shared data between parent/admin views works only within the same browser storage context in this demo.

## Integrating a Real Backend, Authentication, Database, and Payment Gateway
To productionize this project:
1. **Authentication & Authorization:** Implement secure login (hashed passwords, sessions/JWT, CSRF protection), role-based access control (Parent/Admin), and server-side route protection. Replace demo logic in `js/auth.js`.
2. **Database:** Store users, children, enrollments, attendance, learning logs, teacher reports, tuition records, notifications, and enquiries in a database (e.g. PostgreSQL/MySQL) with proper relationships and access controls.
3. **API/Backend:** Create server endpoints for all CRUD operations and dashboard data; replace LocalStorage reads/writes in `js/parent-dashboard.js`, `js/admin-dashboard.js`, and `js/programs.js` with authenticated API calls.
4. **Payments:** Integrate a PCI-compliant payment gateway (e.g. Stripe, Razorpay) via backend-created payment intents/sessions and webhooks; never process real payments purely on the frontend.
5. **Email/Notifications:** Connect a transactional email/notification service for enquiry confirmations and parent updates.
6. **Security & Privacy:** Add input validation/sanitization on the server, HTTPS, audit logging, and privacy-compliant data handling.

## Responsive & Accessibility Notes
- Breakpoint strategy includes 1024px switch to hamburger-only navbar on mobile/tablet (all links/controls inside menu).
- Tested targets: 320px, 375px, 430px, 768px, 1024px, 1366px, 1440px+.
- Semantic HTML, accessible labels, keyboard-friendly controls, and meaningful alt text are included.
- Tables adapt for smaller screens (stacked cards or horizontally scrollable containers). Dashboard sidebars become drawers on small screens.
